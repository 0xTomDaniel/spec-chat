One review service per Herdr session

docs / adr / hosting-per-session.spec.html

Decision behind One service per session.

Context

With one review service per box, every Herdr session on the box would share one registry, server, review index, and log, and each session's operator would see and act on the other's specs.

Rows hold owner panes as bare Herdr pane ids, and Herdr repeats pane ids across sessions, so a service shared by sessions could wake a pane of the wrong session.

The Herdr session is the box's isolation unit; Herdr exports its name to every pane of a named session, and other tools on the box scope their state by the same key.

A box with one session must keep working with nothing moved, and providers plug in once per box, before any named session exists.

Decision

Each Herdr session has its own review service, at a service state named by the session key, the default session's being the one a one-session box already has.

Spec Chat reads the session key from Herdr's own variable, and names Herdr for nothing else: wake still reaches panes only through the wake provider.

Providers stay the box's, in the default session's service state, and every session's service reads them there; a service and its wakes run in its own session.

Why

A service per session isolates registry, index, log, and wake by where state lives, with no session field in any row and no new flag.

The default key keeps the existing service state, so a running box, its unit, its rows, and its links are untouched.

Box providers keep each provider's one registration working for every session, so no provider learns about sessions.

Alternatives rejected

OptionRejected because
One server serving each session's registry under its own pathThe shared server would have to run each wake in another session and keep per-session logs and indexes apart itself
One registry with a session field on every rowEvery reader and command would have to filter by it, and one missed filter mixes sessions again
Providers per sessionA provider registered once per box would be missing from every later session
A Spec Chat variable or flag naming the sessionA second name for a key Herdr already exports, set by hand in every pane

Consequences

A named session's service takes its own port and starts private on loopback; making it public, or putting a front before it, is that session's box setup.

The box user service runs the default session's service; a named session's service starts on its first registration.

Move trigger: if named sessions routinely need public links, revisit one public entry that routes to each session's service.
