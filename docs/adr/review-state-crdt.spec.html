Review state as a grow-only CRDT over the spool

docs / adr / review-state-crdt.spec.html

Decision behind Shared review state: live multi-reviewer review, marks that survive agent edits, and offline merge from a browser on reconnect. Hard to reverse because it fixes the event naming, the stored model, the server's dependencies, and how spec text relates to review state.

Context

The spool already holds one immutable file per event, with unique ids and reference-based causality. That is a grow-only set: two copies merge by union with no conflict.

Three things are missing. The service names files by its own clock, so one event saved twice gets two names. Events do not say which spec text they were written against, so marks cannot follow edits. Events carry no author, and any hand-off sends every reviewer's drafts.

People will edit spec text, but for now only through comments and hand-offs that the agent applies, so during review spec text has one writer, the agent, editing a committed file. Direct live editing by humans is expected later.

The review service is Python standard library only; the runtime is one classic script with vendored libraries and must work over file://.

Decision

Review state is a state-based CRDT built from two grow-only sets in the spool: events named by their writer as <createdAt ns>-<event>-<id>.json, and spec versions stored by SHA-256. Merge is union. Everything else is derived by one deterministic fold and one resolver.

Concurrent edits of one message resolve last writer wins by file name; every edit stays in history.

A mark carries the content hash of the spec text it was written against. Its current place is computed, never stored: locate it in that version, then map it through a character diff to the current text. This replaces the deferred anchor-migration events: nothing is written when the agent edits.

Spec text stays in Git and the worktree file only. Review state never holds a second live copy of it, so there is no step that turns live edits into commits; the existing commit-before-reply rule stays the only one.

No third-party CRDT library while the agent is the one text writer. The service stays standard library and the runtime gains no dependency. Decided by the human, 2026-10-01.

Sync is the existing HTTP /api/events: pages read events not held and write their own idempotently. No WebSocket, so the same route works through the narrow HTTPS relay and an ssh -L tunnel, and no write route ever accepts an agent event.

No login is added. author is a fruit name assigned once per browser, numbered on collision within a spec; it is a label, not an identity. Agent events stay disk-only and event files are never overwritten.

Consequences

One mechanism: the spool is extended, not replaced, and no parallel store is added. watch-specs.sh, cursors, emit-reply.sh, and host wake keep their contracts; a hand-off's batch is the events it lists.

Spool directories grow by one copy of each distinct spec text an event points at; they stay gitignored and are deleted with the spool.

Move trigger: direct human editing of spec text, expected later, or any second concurrent text writer. Then spec text moves to a Yjs document on the page with pycrdt in the service, and the file becomes that document's committed snapshot.

Nothing here blocks that move. Events keep writer-chosen ids and immutable files, which map one to one onto entries of a Yjs map. browser becomes the Yjs client identity. A mark stays a range in a named, stored spec version, which converts to Yjs relative positions by seeding the text from that version; only the resolver changes. No field depends on the diff mapping.

Spec Chat depends on no peer for any of this; no tracker or pane concept enters the model.
