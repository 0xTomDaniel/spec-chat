Comment layer

docs / specs / comment-layer.spec.html

Spec Chat's comments, threads, hand-off, and owner wake serve any page, not only spec pages. A host page loads Spec Chat's comment layer from the review service and marks each thing it shows with an anchor; the layer draws pins, threads, and the composer in place on that thing, and Spec Chat keeps every thread. Spec Chat names no host. Review state stays in Shared review state, the service and its stores in Box review service and providers, and wake in Review host wakes the owner pane.

User stories

As a human looking at something a host page shows, such as a criterion's evidence or an agent's turn, I comment on it in place, starting from the host's starter words, hand off, and read the owner's answer in that thread on the same thing, in a plain browser, in a frame, or on a phone.

As a human reviewer, a comment I write on a criterion from a host page is the spec page's thread at that criterion, so I read one thread wherever I open it.

As the owner of a scope, a hand-off from a host page wakes me like a review hand-off, and my scan gives each comment's subject, kind, label, the address it was written from, and its quote, so I route it, reply, and the human reads my reply where they wrote.

As a host author, I load one script from the review service and mark each thing my page shows with its anchor; I write no comment code and keep no thread, and with no service or no registered scope my page shows no comment control and reads as it does without the layer.

As an operator outside any lane, I register a scope row naming only a scope and my pane, so comments on things in no lane reach me.

Acceptance criteria

Given a human on a host page with an item anchored to a registered scope with starters, a fixture that must be added to provide it, When the human opens the item's comment control, then presses the Question starter, then types the rest of a comment and saves it, Then the item shows a pin, and its thread shows the comment, beginning with Question, as a draft.

Given a human on a host page with an item anchored with three starters, a fixture that must be added to provide it, When the human opens the item's comment control, Then the composer offers the three starters as buttons above an empty comment box.

Given a human on a host page with a draft comment on an anchored item, a fixture that must be added to provide it, When the human presses Hand off, Then the item's thread shows the comment pending.

Given a human on a host page with one draft comment on an item anchored to a criterion of the scope's spec and one on an item whose subject names no spec, a fixture that must be added to provide it, When the human presses Hand off, then opens the thread of the item whose subject names no spec, Then that thread shows its comment pending, and the page counts no drafts left.

Given a human on a host page with an anchored item whose handed-off comment the owner has answered, a fixture that must be added to provide it, When the human opens the item's thread, Then the thread shows the owner's reply under the comment.

Given a human with a host page open on an anchored item whose comment is pending, a fixture that must be added to provide it, When the owner replies in that thread, Then within 2 seconds, without reloading, the item's thread shows the reply.

Given a human with a thread on an item of one host page and another host page anchoring the same subject in the same scope, a fixture that must be added to provide it, When the human opens the other host page, Then its item shows the same thread.

Given a human on a host page with an anchored item, a fixture that must be added to provide it, When the human selects text inside the item, then saves a comment on the selection, Then the item shows the selected text marked, and its thread shows that quote.

Given a human on a host page whose anchored item no longer holds the text a comment on it quoted, a fixture that must be added to provide it, When the human opens that item's thread, Then the thread shows Text removed with the original quote, and its pin sits on the item.

Given a human on a host page with an anchored item, a fixture that must be added to provide it, When the human opens the item's comment control, Then the page shows the composer and Hand off, and no Accept spec, Jev, evidence, or focus on changes control.

Given a human on a phone on a host page with an anchored item with starters, a fixture that must be added to provide it, When the human taps the item's comment control, then taps a starter, then types and saves, Then the item shows a pin, and its thread shows the comment as a draft within the screen's width.

Given a human on a host page that a host serves in a frame with no origin, on a public review service, a fixture that must be added to provide it, When the human saves a comment on an anchored item, then presses Hand off, Then the item's thread shows the comment pending.

Given a human reviewer with a lane's spec under review and a host page anchoring a criterion of that spec in the lane's scope, a fixture that must be added to provide it, When the reviewer saves a comment on that item on the host page, then opens the spec page at that criterion, Then the spec page shows the comment in that criterion's thread, with its kind and a link to the address it was written from.

Given a human reviewer with a comment saved on a criterion on the spec page and a host page anchoring that criterion in the lane's scope, a fixture that must be added to provide it, When the reviewer opens the host page, Then that item's thread shows the spec page's comment.

Given a human on a host page whose item names a scope no registered row has, a fixture that must be added to provide it, When the human opens the page, Then the page shows the item with no comment control and no error.

Given a human on a host page whose review service is stopped, a fixture that must be added to provide it, When the human opens the page, Then the page shows its items with no comment control and no error.

Given a human on a host page at another site's address whose review service is private, a fixture that must be added to provide it, When the human opens the page, Then the page shows its items with no comment control and no error.

Given a host page at another site's address that loads the comment layer from a public review service, When the layer sends its requests, Then the service answers each, its preflight included, so the layer reads the answer, proven by a unit test: no screen shows it.

Given a lane owner whose pane the wake provider finds, with a spec registered under the lane's scope, and a human on a host page anchoring an item whose subject names no spec to that scope, a fixture that must be added to provide it, When the human saves a comment on the item and hands off, Then the owner's pane receives a wake prompt for that hand-off naming the scope, proven by a unit test: no screen shows it.

Given the owner of a scope with a handed-off comment written on a host page about a subject that names no spec, a fixture that must be added to provide it, When the owner scans the scope's hosted threads for ready hand-offs, Then the scan reports the comment with its subject, kind, label, from address, and quote, proven by a unit test: no screen shows it.

Given the owner of a lane with a handed-off comment written on a host page about a criterion of the lane's spec, a fixture that must be added to provide it, When the owner scans that spec for ready hand-offs, Then the scan reports the comment at that criterion with the host's kind, label, and from address, proven by a unit test: no screen shows it.

Given an operator outside any lane whose pane the wake provider finds, When the operator registers a scope row naming only a scope and their pane, Then registration succeeds and reports wake as verified for that pane, proven by a unit test: no screen shows it.

Given an operator with a scope row whose pane the wake provider finds, and a human on a host page anchoring an item to that scope, a fixture that must be added to provide it, When the human saves a comment on the item and hands off, Then the operator's pane receives a wake prompt for that hand-off, proven by a unit test: no screen shows it.

Onboarding: not needed, the layer adds no Spec Chat page; each host's own spec owns its onboarding.

Modular boundaries

The comment layer owns every comment control on a host page: pins, quote marks, threads, the composer and its starters, Hand off, the live read, and the offline outbox. Caller-facing seam: the layer's script address and the anchor attributes a host puts on its elements. Dependency direction: external-provider; a host depends on the layer, the layer depends on the review service's routes, and it names no host. Observable scope: what the layer draws on a host page, and nothing when the service or the scope is absent.

The review service owns where each comment is kept, scope rows, the hosted threads store, and waking a scope's owner. Caller-facing seam: review-host register and remove, and the routes the layer calls. Dependency direction: self-contained; it reads its registry and spools and reaches owners only through the wake provider. Observable scope: registry rows, spool and hosted threads files, and wake prompts.

A host owns its page: which things it shows, the anchor of each, and the review service it loads the layer from. Caller-facing seam: the anchor attributes on its elements. Dependency direction: external-provider; a host depends on Spec Chat, and Spec Chat never on a host. Observable scope: anchors only; a host keeps no copy of a thread and draws no comment control.

The review skill owns the owner's side of hosted threads: the zero-wait scan, replies, and the cursor, as for a spec. Caller-facing seam: the scan's rows, with each hosted comment's subject, kind, label, from address, and quote. Dependency direction: self-contained on disk; it shares the spool module's fold and needs no running service. Observable scope: scan output, agent events, and the cursor.

Hosts and anchors

A host page loads the layer with one script, <url>/static/comment-layer.js, where <url> is the review service's published url. The layer sends every request to the address it was loaded from, never the host page's own address.

The layer gives a comment control to every element of the page carrying a subject, a scope, and a kind, and follows the elements the host adds, changes, or removes, so a host that re-renders keeps its threads.

A comment's quote is the text the human selected inside the element, placed in the element's text by the same resolver as a text mark on a spec page.

How a host whose element draws its text rather than holding it as page text, such as a terminal, gives the layer a selected line as the quote: the Terminal host's lane settles it.

An anchor names a scope, never a pane: no page can make Spec Chat wake an agent the page picks.

Scopes and wake

A scope is the slug of a row registered on the review service the layer loads from. The layer shows a control only on elements whose scope has a row, and reads the scope's rows at each live read, so controls appear and vanish as rows are registered and removed.

A scope row is a row with no spec: review-host register --slug <scope> --owner <pane> with no spec path, as an operator outside any lane registers one for things in no lane. It serves no page and the review index lists no row for it; a lane's spec rows are its scope already.

A scope's owner is the owner its rows name. A comment on a spec wakes that spec's row's owner by the wake rule; a scope's hosted threads wake the owner of the scope's row registered last, by the same rule.

A scope's hosted threads are a spool of the review service, in the same event format and folded by the same folds as a spec's (review state); they live in the hosted threads store and end when the scope's last row is removed.

The layer on a host page

The layer draws the spec page's comment controls, the same pins, threads, composer, replies, edits, resolve, and Hand off, with the same fruit names, live read, and offline outbox (review state), on the element itself; a host page shows no Accept spec, Jev, evidence, or focus on changes control.

The composer offers the element's starters as buttons; pressing one begins the draft with that word, and the comment stays ordinary text.

Hand off hands off this browser's drafts on the page, writing one hand-off into each store that holds them, each listing its drafts (hand-off).

A comment written on a host page shows its kind and a link to its from address on every page that shows its thread, the spec page included.

The layer's controls keep their own look on any host page, and the host page's look is unchanged by them.

With the service unreachable, a private service answering another origin, or no element whose scope has a row, the layer draws nothing and shows no error, and the host page reads as it does without the layer.

In a frame with no origin, the layer's fruit name, outbox, and drafts last until the page reloads, as for a spec page served at another address.

Proof

Seam: the service's placement of a comment by subject and scope, and the hosted threads spool, tested as pure functions over fixture registries and spools; the layer through a fixture host page in a browser test, served directly, at another origin, and in a frame with no origin.

First failing test: a comment whose subject is a criterion ID of a spec its scope's row serves is stored in that spec's spool at that anchor, and one whose subject names no spec is stored in the scope's hosted threads.
