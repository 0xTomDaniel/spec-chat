01

User stories

One reviewer, one page, consistent chrome.

As a spec reviewer, I see one coherent visual system across every button, pill, pin, panel, popover, toolbar, and bar on a spec page, so I never wonder whether two differently styled controls do the same thing.

As a contributor editing runtime.js, every chrome color, font size, weight, radius, and spacing value is a named token from one block, so I never invent an ad hoc value or guess which grey to use.

02

Acceptance criteria

Screenshots at 1440 and 390, before and after.

Given the CSS const string in runtime.js, it opens with one :root block headed /* ui tokens */ holding the index tokens plus the additions in the token additions table, and every chrome color, font-size, font-weight, border-radius, and spacing value in the CSS const is a var(--ui-*) reference, with no remaining literal values except pin teardrop border-radius, z-index, transition, animation, and position values.

At 1440 and 390 widths, every chrome button matches one of the four button variants (primary, secondary, icon, text-link) with the specified shared properties, and no button has a shape, size, radius, font, or color outside the system.

At 1440 width with draft, acknowledged, and resolved threads, every pin, pill, dock thread, and thread card border for the same status uses the same token pair (color on soft background), and no two statuses share a color.

With Jev markers at important, neutral, and passed levels, marker colors are --ui-marker-important #d1242f, --ui-marker #767b85, and --ui-marker-pass #1a7f37 with their current shapes and sizes.

For every chrome text-on-background combination, normal text meets 4.5:1 contrast ratio and meaningful non-text boundaries (status pill borders, active thread borders, pin outlines) meet 3:1.

At 1440 and 390 widths on a spec with the shared stylesheet, the spec document content (headings, prose, tables, figures, code blocks, section borders, page background) renders identically to the current main branch: the spec.css tokens and DOC_CSS article.spec rules are unchanged.

In dark mode (prefers-color-scheme: dark), all chrome surfaces, text, and borders use token overrides from the dark :root block, and no literal light-mode color leaks through.

Given the diff of this branch against main, only CSS const string content in runtime.js is changed (no JS logic, no function signatures, no event handling), and both copies of runtime.js are identical.

03

Modular boundaries

Self-contained CSS refactor.

The CSS const strings in runtime.js own all spec page chrome styling: layout, color, typography, and responsive rules for the annotation overlay (toolbar, panel, dock, pins, pills, popovers, toasts, banners, badges, error overlay, range bar, index link, Jev notes, orphan hints, composer, settings). The caller-facing seam is the set of CSS class names and data attributes already used in mountUI() and render functions. No class name changes; the same selectors get new property values from tokens. Self-contained: no new external dependency. The token block is a CSS custom property declaration within the same file. Observable scope: every chrome element on a spec page uses the unified token set. The spec document's own content styling is outside this boundary.

04

Design

One token block, one button system, one color per meaning.

Token block

The spec page chrome CSS const (the CSS string in runtime.js) opens with one :root block headed /* ui tokens */, holding exactly the index tokens plus the additions in the table below. Every chrome rule uses only these variables. No literal color, font size, weight, spacing, or radius value appears in a chrome rule. The spec document's own content styling (DOC_CSS article.spec rules and spec.css) is unchanged and keeps its own --spec-* tokens.

Button system

Every chrome button is one of four variants. All share: font-family: var(--ui-font), font-size: var(--ui-text-xs) (12px), font-weight: 600, border-radius: var(--ui-radius-sm) (6px), min-height: 32px desktop / 44px mobile, padding: var(--ui-space-2) var(--ui-space-3) (8px 12px). Focus: outline: 2px solid var(--ui-focus); outline-offset: 2px.

Typography

Chrome text uses only the index type scale. var(--ui-text-xs) 12px: pills, badges, captions, toolbar status, note meta, popover text, dock threads. var(--ui-text-sm) 14px: panel body, thread messages, composer textarea, range bar text, Jev note. var(--ui-text-md) 16px: mobile composer textarea (iOS zoom prevention). var(--ui-text-lg) 20px: panel toggle glyph. Weights: 400 body, 600 emphasis and buttons, never 700 or 750.

Spacing and geometry

Chrome spacing uses only the index spacing scale: 4, 8, 12, 16, 24, 32px. Border radii: var(--ui-radius) 8px for containers (panel, toolbar, dock, popover, toast), var(--ui-radius-sm) 6px for buttons and inputs, var(--ui-radius-pill) 999px for pills and badges. Pin border-radius is unchanged (teardrop shape).

06

Coordinate lanes

What changes, what does not, how merges work.

This spec changes only the CSS const strings in runtime.js: CSS, and the chrome portion of DOC_CSS (the dark mode overrides for the overlay, not the article.spec rules). No JS logic changes. #91 (jev-yes-no) and the Reconcile offer detail lane both add or change JS logic and may add CSS rules. Merge conflicts will be in the CSS template strings. Resolution: take this branch's token block and color/button values; take the other branch's new selectors and rules, rewriting their literal values to use the tokens.

runtime.js exists in two identical copies: skill/review-spec/assets/viz/runtime.js (source) and docs/specs/.viz/runtime.js (committed for offline use). Both are updated together.
