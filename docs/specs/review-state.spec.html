Shared review state

docs / specs / review-state.spec.html

One spec's review state is a conflict-free replicated set: several reviewers write it live, the agent edits the spec under it, and copies held offline merge without loss. The spool beside each spec stays the one store; the decision and its tradeoff live in the review state CRDT ADR. The box service, its URL, and providers stay in Box review service and providers; owner wake stays in Review host wakes the owner pane.

User stories

As a human reviewer reviewing a spec with others, I see their comments, replies, edits, and resolutions on my open page as they save them, and nothing any of us saves is lost or overwritten.

As one of several reviewers, my hand-off sends my drafts and leaves another reviewer's unfinished drafts with them.

As a human reviewer, when the agent edits the spec during review, each of my marks stays on the text I marked, and the thread tells me when that text changed or is gone.

As a human reviewer on a laptop, I keep reviewing an open page when the connection drops, and everything I saved merges when it returns.

As the owning agent, I keep the same scan, cursor, and reply contract, and I read each mark at its current place in the spec I am editing.

Acceptance criteria

Given two reviewers with the report spec of the spec review site fixture open in two browsers. When the first reviewer saves a comment on a block. Then within 2 seconds, without reloading, the second reviewer's page shows that pin and its thread with the first reviewer's name.

Given two reviewers with the report spec of the spec review site fixture open in two browsers. When both save a comment on the same block within the same second. Then each page shows both threads on that block, each exactly once, each with its author's name.

Given a reviewer opening the report spec of the spec review site fixture for the first time in this browser. When they save a comment, then reload the page and save a reply. Then no name prompt appears, and both messages show the same tropical fruit name from the page's fruit list as their author.

Given two reviewers whose browsers were assigned the same fruit name, on a fixture that must be added to provide those two browsers. When each saves a comment on the report spec. Then both pages show the earlier commenter as that fruit name and the other as that name followed by 2.

Given two reviewers viewing one pending human message, on a fixture that must be added to provide a spec with a pending thread. When both save an edit to that message. Then both pages show the same text for it, the later save's, and its thread history lists both edits with their authors.

Given a reviewer saving a comment on the report spec of the spec review site fixture, needs an induced failure: the service's response to the save is lost. When the page sends the same comment again. Then the spec's thread list shows that comment exactly once.

Given two reviewers each with one draft comment on the report spec of the spec review site fixture. When the first reviewer presses Hand off. Then on both pages the first reviewer's thread shows pending and the second reviewer's thread still shows draft.

Given a reviewer's comment on a selected sentence, on a fixture that must be added to provide a spec with such a thread. When the agent inserts a new paragraph above that sentence and the page refreshes. Then the pin sits on the same sentence, and the thread shows no change notice.

Given a reviewer's comment on a selected sentence, on a fixture that must be added to provide a spec with such a thread. When the agent rewrites part of that sentence and the page refreshes. Then the pin sits on the sentence's remaining text, and the thread shows Text changed since this comment with the original quote.

Given a reviewer's comment on a selected sentence, on a fixture that must be added to provide a spec with such a thread. When the agent deletes that sentence and the page refreshes. Then the thread shows Text removed with the original quote, and its pin sits on the nearest surviving anchored block.

Given a reviewer composing a comment on a sentence of a page they loaded before the agent inserted a paragraph above it, on a fixture that must be added to provide that edit. When they save the comment. Then after refresh the pin sits on that same sentence in the current spec.

Given a handed-off comment whose sentence the agent has since rewritten, on a fixture that must be added to provide it. When the agent runs the zero-wait scan. Then the scan prints the same file-name rows as before, and the event's printed location and state are the ones the page shows for that thread.

Given two reviewers' hand-offs on the report spec of the spec review site fixture. When the agent processes the scan's batch and appends those file names to its cursor. Then the next zero-wait scan exits 3, and both reviewers' threads show acknowledged once replies exist.

Given a reviewer with the report spec of the spec review site fixture open. When their browser goes offline and they save a comment. Then the page shows Offline: 1 change waiting and the new thread as a draft.

Given a reviewer offline with one waiting comment on the report spec of the spec review site fixture, and a second reviewer who commented meanwhile. When the first reviewer's browser comes back online. Then within 2 seconds the waiting notice is gone and both pages show both comments, each exactly once.

Given a reviewer who saved a comment offline on the report spec of the spec review site fixture and then closed the tab. When they open the same page again with the service reachable. Then the comment appears as their draft, and another reviewer's page shows it.

Given two reviewers with the report spec of the spec review site fixture open in two browsers. When the second reviewer looks at the page before anyone saves anything. Then the page shows the spec and its review controls with no list of viewers and no other reviewer's selection.

Onboarding: not needed, shared state extends the review page with no new user surface.

Modular boundaries

The review service owns each spec's review state: storing events and spec versions idempotently, and resolving every mark to its place in the current spec. Caller-facing seam: /api/events, read with resolved places and written idempotently, and the spool directory beside the spec. Dependency direction: self-contained; it reads spec files and local Git and never writes repository state. Observable scope: spool files, version files, and /api/events responses.

The browser runtime owns showing shared state live, the browser's assigned fruit name, and the offline outbox of saved events not yet stored. Caller-facing seam: the page, and /api/events toward the service. Dependency direction: external-provider; the runtime depends on the service route, never the reverse. Observable scope: pins, threads, statuses, and the offline notice.

The review skill owns the agent side: zero-wait scan, batch processing, spec edits, replies, and cursor advance. Caller-facing seam: the scan's rows and the spool and cursor files. Dependency direction: self-contained on disk; it shares the service's resolver and needs no running service. Observable scope: scan output, agent events, and cursor contents.

Git owns spec text; the spec file in the worktree is the only live copy of it. Caller-facing seam: the spec file and its commits. Dependency direction: self-contained; review state points at spec versions by content hash, and Git never depends on review state. Observable scope: the spec file and its history.

Document model

Each spec's review state is two grow-only sets in its spool, plus values every reader derives the same way from them. Merging two copies is set union; nothing stored is ever changed or deleted.

Two folds exist, one per language, and give the same threads and statuses for the same events: the page's, in the runtime, and the service fold, in the review skill's spool module, which every service and agent reader uses, among them the review index and Jev. A second fold in Python is not added.

Every human event carries browser, a random id the page creates once and keeps in this browser, author, the fruit name assigned to that browser, and version, the content hash of the spec text the page showed when it was written. The hash is the one the service already sends as the page's ETag.

On first use, a browser is assigned one name at random from a fixed list and keeps it: Mango, Papaya, Lychee, Guava, Rambutan, Pineapple, Passion Fruit, Dragon Fruit, Durian, Jackfruit, Mangosteen, Starfruit, Soursop, Coconut, Banana, Tamarind, Longan, Feijoa, Cherimoya, Sapodilla, Kiwano, Pitanga, Jabuticaba, Salak. No name prompt appears. Decided by the human, 2026-10-01.

Within one spec, browsers sharing a fruit name are numbered by their first event's file name: the first shows the name alone, the next adds 2, then 3. Every reader derives the same names, so authors stay distinct on every page.

File-name order breaks ties only between edits of one message; meaning follows references (respondsTo, threadId, supersedes), so a skewed clock changes at most which of two racing edits shows.

A message with more than one edit shows the effective text, and its thread history lists every edit with its author.

Live review

The page asks the service for events it does not hold at least every 2 seconds, and shows them without reloading.

The page names each event before sending it, so a resend after a lost response stores nothing new.

A hand-off lists the event ids it hands off in events: its browser's drafts. Only those become pending; other reviewers' drafts stay drafts. A hand-off without events hands off every draft.

Accept spec is offered when every thread is resolved and no open TBD remains, whoever's thread it is, and writes the existing empty hand-off.

The page shows no presence: no list of who is viewing and no live selections or cursors. Authors appear only on what they saved. Decided by the human, 2026-10-01.

Marks through agent edits

The resolver finds a mark's source range in its event's version: the anchored block, then the target within it, the quote for a text target.

It maps that range through a character diff from that version to the current spec text, and reports the current block, range, and state below. The same inputs give the same answer on every reader.

An event with no version resolves by anchor and quote in the current spec.

The agent is the one writer of spec text. It edits the spec file in the worktree, Git stays the truth for that text, and marks follow by the diff mapping above. Reviewers change spec text only through comments and hand-offs that the agent applies; the page offers no direct text editing. Decided by the human, 2026-10-01.

When the agent rewrites text a reviewer is commenting on, the edit lands and is never held back; the mark stays attached and shows changed or gone by the table above, including a comment saved from a page loaded before the edit. Decided by the human, 2026-10-01.

Offline

The page keeps every event it saved and has not seen stored in browser storage for that page, and the events it last loaded.

While any saved event is not yet stored, the page shows Offline: n changes waiting, keeps every review action available, and sends the events in order as soon as the service answers.

A page opened later with waiting events sends them first, then reads.

A waiting hand-off wakes the owner when the service stores it, by the existing wake rule.

Trust

The page has no login and its URL is not an authentication boundary. author is an assigned fruit name, not an identity, and is never checked.

Agent events are written only on disk; the service refuses an agent event over HTTP, so no page can speak as the agent.

The service never overwrites an event file; a write naming an existing file with different bytes is refused.

Proof

Seam: the resolver and the idempotent event write, tested as pure functions over fixture spec versions and spool directories; the page through the existing runtime tests.

First failing test: an event resolved against a spec with a paragraph inserted above its quote reports state kept at the shifted range.
