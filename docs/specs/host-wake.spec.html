Review host wakes the owner pane

docs / specs / host-wake.spec.html

Source issues: ANN-131.

Replaces the per-lane external monitor in Review wake ownership. The one long-lived review host already knows each resource's owner pane from its registry, so it wakes that pane itself.

User stories

As a human reviewer, when I hand off a batch, the owning agent wakes without anyone having started a monitor for that lane.

As a human reviewer, when the owner pane is gone, the page tells me wake failed so I resume by chat instead of waiting.

As a lane owner, registering my spec with my pane id is the whole wake setup; I may end my turn and the next hand-off prompts my pane.

As a human reviewer on a host without Herdr, review works as before and the page keeps its existing timeout message.

Acceptance criteria

Given a registered resource whose owner pane is idle, when the human completes a hand-off, the host runs herdr-say to that owner pane exactly once for that batch, within a few seconds, and never again while the batch is unchanged.

When a later hand-off adds events, before or after the owner advances its cursor, the host wakes the owner once for the new batch.

When the owner pane is working, or herdr-say exits 75 because it is blocked, the host sends nothing now and retries on each poll until one delivery succeeds.

When herdr agent get fails for the owner pane, or delivery fails otherwise, while a hand-off waits, the page shows wake failed; send a new chat message to resume, and the host keeps retrying so a re-registered owner is woken.

When Herdr is not installed on the host, the host sends nothing, register prints wake=unavailable, and the page keeps the existing timeout message.

When review-host register succeeds, it prints wake=verified owner=<pane> only when Herdr resolves that owner pane, and wake=unavailable owner=<pane> otherwise; registration never fails on wake.

After this change, review-control.sh external, wake-herdr.py, the adapter environment contract, and the Herdr monitor instructions no longer exist; yielded and manual are unchanged.

Modular boundaries

The review host owns detecting a complete hand-off batch per registered resource and waking that row's owner once per batch. Caller-facing seam: registry rows (owner, cursor_name, spec) in, one herdr-say per batch out, and the wake state on /api/events. Dependency direction: external-provider; the host calls Herdr, and Herdr never calls the host. Observable scope: delivered prompts, register output, and the page wake message.

The woken owner owns everything after wake: zero-wait scan, batch transaction, replies, and cursor advance. Caller-facing seam: the wake prompt text and the existing spool and cursor files. Dependency direction: self-contained; the host never reads comments, edits specs, writes the spool, or advances cursors. Observable scope: agent replies and cursor contents.

Wake rule

The host polls every registered resource's spool every 3 seconds, in one background thread of the running review server.

A batch is the resource's human events not in its cursor, through the newest completed hand-off, exactly as the zero-wait scan reports it. Its identity is that list of file names.

Delivered batch identities live only in memory. After a host restart, a still-unprocessed batch is woken once more; a duplicate wake is harmless because the owner starts with a zero-wait scan.

The prompt names the spec path, collection root, cursor name, and event count, and tells the owner to run the zero-wait scan, process the batch, and park.

Control states

The external-wake state becomes host-wake: the resource is registered with the owner's Herdr pane id and register printed wake=verified. A final response is allowed.

Turn-yielded and manual-resume are unchanged. A registration that printed wake=unavailable selects manual-resume.

The row's owner is the lane record owner pane id, never an agent or tab name.
