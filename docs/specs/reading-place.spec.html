Keeping the reader's place

docs / specs / reading-place.spec.html

A spec page reopens where its reader was: a reload, or Back after a host reloads its frame, returns to the same section and offset; an anchor in the address wins.

User stories

As a reviewer, when a spec page reloads, including after I go to Proof and back with Spec alone in BB, it returns me to where I was reading.

Acceptance criteria

Given a reviewer reading a spec, When the reviewer scrolls to a later section, then reloads the page, Then the page returns to that section at the same offset, not the top.

Given a reviewer reading a spec with evidence in Spec alone in BB, a fixture must be added to provide it, When the reviewer scrolls to a later section, then opens a criterion's evidence, then goes Back, Then the page returns to that section at the same offset, not the top.

Given a reviewer reading a spec, When the reviewer scrolls to a later section, then opens the spec at an address naming another anchor, Then the page opens at that anchor, with no error shown.

Given a reviewer whose browser storage is disabled, When the reviewer scrolls a spec to a later section, then reloads the page, Then the page opens at the top, with no error shown.

Given a reviewer reading a spec, needs an induced failure: browser storage throws, When the reviewer scrolls to a later section, then reloads the page, Then the page opens at the top, with no error shown.

Given a reviewer whose place in a spec was kept at a section an edit has since removed, a fixture must be added to provide it, When the reviewer opens the spec, Then the page opens at the top, with no error shown.

Onboarding: not needed, the kept place adds no user surface. One hand-off control for desktop and phone: not affected, the kept place adds no control (phone rule, desktop rule). Any origin only without login or cookie: kept, the place adds no login and no cookie (rule). Every mockup at production fidelity: not affected, the kept place draws no screen (rule). Threads read as one conversation: not affected, the kept place adds no thread view (rule). Never strip proof clauses or rewrite unedited criteria: not affected, no criterion here carries a proof clause (shaping rule, repair rule).

Modular boundaries

The browser runtime owns the reader’s place: per spec path, the nearest section anchor at the top of the viewport and the offset from it, in this browser’s storage. Caller-facing seam: the page’s load and scroll, and its address’s fragment. Dependency direction: self-contained; it reads and writes only browser storage, never the service. Observable scope: where a spec page opens.

Keeping the reader's place

The runtime remembers, per spec path, the nearest section anchor at the top of the viewport and the scroll offset from it, in the browser's local storage.

On load, once the page has rendered, it scrolls back to that anchor plus the offset; an anchor in the address wins, and a missing anchor or no record leaves the page at the top.

A sandboxed frame, a full quota, or disabled storage never breaks the page; the place is then simply not kept.

This makes Spec alone in BB keep its place across an evidence open and Back, where BB reloads the frame.
