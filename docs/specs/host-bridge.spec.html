Host bridge

docs / specs / host-bridge.spec.html

A host that frames a Spec Chat page, such as a BB plugin, says hello naming what it opens. The page then asks it to open evidence or a new tab and tells it its title. Unframed, or before a hello, every link keeps the browser's own behavior. Pages a shell holds extends the hello with comments.

User stories

As a reviewer inside the BB plugin, evidence links open in the plugin's Proof page instead of a browser.

As a reviewer inside a host that offers tabs, a new-tab click on a link to another Spec Chat page, on a spec page or the review index, opens it in the host's own tab instead of a browser, while plain clicks and links to other sites keep the browser's own behavior.

Acceptance criteria

Given a reviewer viewing a spec with evidence inside the BB plugin, a fixture must be added to provide it, When the reviewer opens a criterion's marker popover and clicks its evidence label, Then the plugin's Proof page opens on that bundle at that criterion, and no browser tab opens.

Given a reviewer viewing a spec with evidence inside the BB plugin, a fixture must be added to provide it, When the reviewer opens a criterion's marker popover and clicks its bundle link, Then the plugin's Proof page opens on that bundle, and no browser tab opens.

Given a reviewer viewing a spec with evidence in a plain browser tab, a fixture must be added to provide it, When the reviewer opens a criterion's marker popover and clicks its evidence label, Then the evidence service's bundle page opens at that criterion.

Given a reviewer viewing a spec with evidence in a frame whose host never announces itself, a fixture must be added to provide it, When the reviewer opens a criterion's marker popover and clicks its evidence label, Then the evidence service's bundle page opens at that criterion.

Given a reviewer on a spec page framed by a host whose hello offers tabs, When the reviewer opens the page, Then the page answers the host with its title, proven by a unit test: no screen shows it.

Given a reviewer on macOS on a spec page framed by a host whose hello offers tabs, When the reviewer Cmd+clicks a link to another spec on the same server, Then the page stays where it is and asks the host for a new tab at that link's full address, proven by a unit test: no screen shows it.

Given a reviewer on a system other than macOS, on a spec page framed by a host whose hello offers tabs, When the reviewer Ctrl+clicks a link to another spec on the same server, Then the page stays where it is and asks the host for a new tab at that link's full address, proven by a unit test: no screen shows it.

Given a reviewer on a spec page framed by a host whose hello offers tabs, When the reviewer middle-clicks a link to another spec on the same server, which needs a three-button mouse, Then the page stays where it is and asks the host for a new tab at that link's full address, proven by a unit test: no screen shows it.

Given a reviewer on macOS on the review index framed by a host whose hello offers tabs, When the reviewer Cmd+clicks a spec link, Then the index stays showing and the index answers the hello with its title and asks the host for a new tab at that spec's full address, proven by a unit test: no screen shows it.

Given a reviewer on a system other than macOS, on the review index framed by a host whose hello offers tabs, When the reviewer Ctrl+clicks a spec link, Then the index stays showing and the index answers the hello with its title and asks the host for a new tab at that spec's full address, proven by a unit test: no screen shows it.

Given a reviewer on a spec page framed by a host whose hello offers tabs, a fixture must be added to provide it, When the reviewer plainly clicks a link to another spec on the same server, Then that spec loads in place and no tab request is sent.

Given a reviewer on macOS on a spec page framed by a host whose hello offers tabs, When the reviewer Cmd+clicks a link to another site, Then the browser handles the link with its own new-tab behavior and no tab request is sent, proven by a unit test: no screen shows it.

Given a reviewer on macOS on a spec page in a plain browser tab, When the reviewer Cmd+clicks a link to another spec on the same server, Then the browser opens it in a new browser tab and no message is sent, proven by a unit test: no screen shows it.

Given a reviewer on macOS on a spec page framed by a host whose hello offers only evidence, When the reviewer Cmd+clicks a link to another spec on the same server, Then the browser handles the link with its own new-tab behavior and no tab request is sent, proven by a unit test: no screen shows it.

Given a reviewer on macOS on a spec page framed by a host, to which a window other than its parent sent a hello offering tabs, When the reviewer Cmd+clicks a link to another spec on the same server, Then the page has sent no title, and the browser handles the link with its own new-tab behavior, proven by a unit test: no screen shows it.

Modular boundaries

A framing host, such as a BB plugin, owns what it opens on an open request or a tab request; Spec Chat owns only the bridge messages and which of its own link clicks are new-tab clicks. Caller-facing seam: the plugin bridge messages. Dependency direction: external; the host frames Spec Chat and answers its requests; Spec Chat imports no host code and works unframed. Observable scope: the page the host opens.

Opening in the plugin

StepFromMessage
1Plugin, to the framed page on load{type: "spec-chat-host", opens: ["evidence"]}
2Page, to that sender's origin on a label or bundle click{type: "spec-chat-open-evidence", bundle, criterion}; criterion only for the label
3PluginOpens its Proof page on that bundle, and that criterion when given
4Page, to that sender's origin, on a hello whose opens contains "tab"{type: "spec-chat-title", title}; title the document title as a string
5Page, to that same window and origin, on a new-tab click on a link to the page's own origin, after step 4{type: "spec-chat-open-tab", href}; href the link's absolute address as a string

Only after step 1 does the page turn an evidence click into step 2 instead of following the link; before it, and in any unframed page, links keep the browser's own behavior.

The page takes a hello only when event.source is its parent window and event.origin is a real origin, not null, and answers to event.source at event.origin. opens must be an array; "evidence" and "tab" each turn on only their own steps, and "comments" turns on only the shell messages, from an origin the box names as a shell.

A new-tab click is a Cmd+click on macOS, a Ctrl+click elsewhere, or a middle-click, on a link whose resolved address has the origin of the page's own address. On it the page cancels the click's default and sends step 5. A plain click, a click on a link to another origin, and any click before a tab hello keep the browser's own behavior, and a page that is not framed sends nothing.

Spec pages and the review index both speak steps 4 and 5, and the index’s lane Proof link speaks step 2 with its bundle alone (review facts). One mechanism: the tab steps use the one hello listener and its sender check, and the index runs the same bridge code as spec pages, not a second copy; the index loads nothing else from the runtime.

Proof: the deep-module seam is the page's message and click handling given a parent window, a hello, and a click; the first failing test sends spec-chat-open-tab for a Cmd+click on a same-origin link after a tab hello and sends nothing for a plain click or before the hello.

bundle and criterion are the evidence service's bundle ID and criterion ID, not URLs, so the plugin opens only its own Proof page.
