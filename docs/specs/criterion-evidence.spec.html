Each acceptance criterion on the spec page shows what its newest evidence proves about the text being read. The evidence read is owned by annotateanything docs/specs/evidence-site.spec.html#criteria-read; Spec Chat holds no annotateanything code and only renders the answer.

In spec-driven development behavior changes only with a spec change, so a text-matched Passed is proof of what the spec promises now, and Stale on an unchanged-looking spec exposes unspecced behavior change.

User stories

As a reviewer, each acceptance criterion tells me whether its newest evidence proves the text I am reading, so I know what is actually proven.

As a reviewer, one click on the evidence label in a criterion's marker popover opens its evidence, and a small link opens the whole bundle.

As a reviewer on a lane worktree or on main, evidence notes judge the text of the tree I am viewing.

As a reviewer, when the evidence service is down or not configured, the page works as today, with no evidence notes.

Acceptance criteria

When a criterion's newest evidence whose proven text matches the criterion as read passed, and another's failed, their marker popovers show Passed and Failed, each with #<PR> · <age>.

When no evidence matches, the newest evidence passed, and Jev judges the text change cosmetic, its marker popover shows Passed · reworded.

When no evidence matches and Jev judges the change material, is unsure, off, or unavailable, or the criterion has an uncommitted edit, its marker popover shows Stale with the newest evidence's context and links, and its marker is colored.

When a criterion has no evidence, its marker popover shows Not yet with no context and no links.

When the picked evidence's tested commit is not on main, and another's is, only the first adds not on main to its context.

When the reviewer clicks the evidence label in a popover, then its bundle link, the label opens that criterion's artifact and the link opens the bundle page, both on the evidence service.

When a lane worktree rewords a criterion materially and main does not, the lane's page shows Stale and main's page shows Passed for the same criterion ID.

When the evidence service is down, errors, or is not configured, no evidence note and no error show, and the page, review controls, spool, and spec acceptance eligibility are unchanged.

When a spec page loads, it renders at once and evidence notes arrive after it, without reflowing text or moving review controls.

When the page is 375px wide, a tap on a criterion's marker opens its evidence note with no horizontal page drift, and every label is 4.5:1 readable.

When a client sends parameters beyond the spec path, the review server ignores them.

Modular boundaries

The review server owns one evidence read per page: it names the spec and the tree being viewed, marks uncommitted criteria, and makes links absolute. Caller-facing seam: GET /api/evidence?path=<spec>, returning one entry per criterion anchor, or none. Dependency direction: calls the evidence service as an external provider over HTTP; reads local Git and served specs; imports no annotateanything code. Observable scope: the JSON response, in single-root and registry modes.

The browser runtime owns each evidence note's label, context, and links inside the marker popover that jev-suggestions defines. Caller-facing seam: the rendered evidence notes. Dependency direction: self-contained within Spec Chat; consumes the server route; holds no matching, Jev, or Git logic. Observable scope: what the reviewer sees.

The annotateanything evidence service owns which evidence is picked, text matching, the Jev judgment, and on main. Caller-facing seam: GET /criteria, as evidence-site#criteria-read defines. Dependency direction: external provider; it never calls Spec Chat. Observable scope: its JSON response.

Evidence note

Every data-acceptance-criterion on an HTTP-served spec gets an evidence note, listed first in its marker popover, once evidence loads; a criterion with no other note gets a marker for it.

An evidence note is a state label in words, a muted context line, and a small bundle link. Only Stale colors the marker; every other state leaves it neutral.

Matching text, passedNot askedPassed
Matching text, failedNot askedFailed
Newest, text differscosmeticPassed · reworded or Failed · reworded
Newest, text differs, or criterion edited but uncommittedmaterial, unsure, off, or unavailableStale
NoneNot askedNot yet

Every label but Not yet has context #<PR> · <age>, plus not on main when so; the label opens the artifact and bundle opens the bundle page. Not yet has neither.

Age is the capture time relative to now: minutes, hours, or days, as 5 m, 3 h, 2 d.

A picked evidence with no valid artifact makes the label plain text; bundle still opens the bundle page.

Evidence notes never change a spec, the spool, a thread, or spec acceptance eligibility, and never hide or reorder content.

One read per page

The review server reads the evidence service's public base URL from SPEC_CHAT_EVIDENCE_URL in its environment; unset means no read and no evidence notes.

The criterion ID is branch-free, project/<project-id>::<spec path>#<anchor>, as evidence records it; the project ID is the last path part of the served root's origin URL without .git, such as spec-chat.

The viewed commit is the serving root's head, so a lane worktree and main each judge their own text.

A criterion whose served bytes differ from its bytes at head is marked uncommitted and shows Stale, because the evidence service judges committed text only.

The service's relative artifact and bundle paths are joined to SPEC_CHAT_EVIDENCE_URL before they reach the browser.

A timeout, error, or non-JSON answer returns no entries; the server does not retry, and the next page load asks again.

Proof

First failing test: the review server, given a fake evidence service answering one matching pass and one material mismatch, returns Passed and Stale entries with absolute links.

Evidence: server and runtime tests behind a fake evidence service, and a QA bundle driven by the Jev driver on a real spec served with the real evidence service.

Non-goals
