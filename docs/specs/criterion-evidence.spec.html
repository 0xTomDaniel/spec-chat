Each acceptance criterion on the spec page shows what its newest evidence proves about the text being read. The evidence read is owned by annotateanything docs/specs/evidence-site.spec.html#criteria-read; Spec Chat holds no annotateanything code and only renders the answer.

In spec-driven development behavior changes only with a spec change, so a text-matched QA passed is proof of what the spec promises now, and QA stale on an unchanged-looking spec exposes unspecced behavior change.

User stories

As a reviewer, each acceptance criterion tells me whether its newest evidence proves the text I am reading, so I know what is actually proven.

As a reviewer, one click on the evidence label in a criterion's marker popover opens its evidence, and a small link opens the whole bundle.

As a reviewer on a lane worktree or on main, evidence notes judge the text of the tree I am viewing.

As a reviewer, a QA stale or reworded criterion shows me what changed between the proven text and the text I am reading, so I judge the gap without opening anything.

As a reviewer, a QA stale criterion offers one button that drafts a re-proof request; the request reaches the spec's owner, who acts on it.

As a reviewer inside the BB plugin, evidence links open in the plugin's Proof page instead of a browser.

As a reviewer, when a spec page reloads, including after I go to Proof and back with Spec alone in BB, it returns me to where I was reading.

As a reviewer, when the evidence service is down or not configured, the page works as today, with no evidence notes.

Acceptance criteria

When a criterion's newest evidence whose proven text matches the criterion as read passed, and another's failed, their marker popovers show QA passed and QA failed, each with #<PR> · <age>.

When no evidence matches, the newest evidence passed, and Jev judges the text change cosmetic, its marker popover shows QA passed · reworded.

When no evidence matches and Jev judges the change material, is unsure, off, or unavailable, or the criterion has an uncommitted edit, its marker popover shows QA stale with the newest evidence's context and links, and its marker is colored.

When a criterion has no evidence, its marker popover shows No QA yet with no context and no links.

When the picked evidence's tested commit is not on main, and another's is, only the first adds not on main to its context.

When the reviewer clicks the evidence label in a popover, then its bundle link, the label opens the bundle page scrolled to that criterion with its artifact open large in place, not at the bundle top, and the link opens the bundle page at its top, both on the evidence service.

When a lane worktree rewords a criterion materially and main does not, the lane's page shows QA stale and main's page shows QA passed for the same criterion ID.

When criteria show QA passed, QA failed, QA stale, and No QA yet, in light and in dark theme, their markers are a green check, a colored !, a colored !, and a gray dot, each mark 3:1 readable, and hovering any of them opens its popover.

When a criterion shows QA stale, QA passed · reworded, or QA failed · reworded, its evidence note shows the proven text against the text as read as one inline diff, removed words struck through and added words underlined, and a matching QA passed or QA failed shows no diff.

When the reviewer clicks Ask for re-proof on a QA stale note, the comment composer opens at that criterion with the re-proof draft filled in, and nothing is written until the reviewer sends it.

When a note is QA passed, QA failed, reworded, or No QA yet, it shows no Ask for re-proof button.

When a sent re-proof request is handed off on a lane spec, and on a main spec, the lane owner pane, and the operator pane, is woken with the batch like any comment.

When the page runs inside the BB plugin and the reviewer clicks an evidence label or bundle, the plugin's Proof page opens on that bundle, at that criterion for the label, and no browser tab opens.

When the same page runs in a browser tab, or in a frame whose host never announces itself, evidence links open on the evidence service as today.

When the reviewer scrolls a spec to a later section and the page reloads, including Spec alone in BB after an evidence open and Back, the page returns to that section at the same offset, not the top.

When the address names an anchor, or browser storage is unavailable or throws, or the remembered section no longer exists, the anchor wins, or the page opens at the top as today, with no error shown.

When the evidence service is down, errors, or is not configured, no evidence note and no error show, and the page, review controls, spool, and spec acceptance eligibility are unchanged.

When a spec page loads, it renders at once and evidence notes arrive after it, without reflowing text or moving review controls.

When the page is 375px wide, a tap on a criterion's marker opens its evidence note with no horizontal page drift, and every label is 4.5:1 readable.

When a client sends parameters beyond the spec path, the review server ignores them.

Modular boundaries

The review server owns one evidence read per page: it names the spec and the tree being viewed, marks uncommitted criteria, and makes links absolute. Caller-facing seam: GET /api/evidence?path=<spec>, returning one entry per criterion anchor, or none, plus the levels table as levels. Dependency direction: calls the evidence service as an external provider over HTTP; reads local Git and served specs; imports no annotateanything code. Observable scope: the JSON response, in single-root and registry modes.

The browser runtime owns each evidence note's label, context, and links inside the marker popover that jev-suggestions defines. Caller-facing seam: the rendered evidence notes. Dependency direction: self-contained within Spec Chat; consumes the server route; holds no matching, Jev, or Git logic. Observable scope: what the reviewer sees.

The BB plugin owns navigating to its Proof page on an open request; annotateanything docs/specs/workbench-system.spec.html governs it. Caller-facing seam: the plugin bridge messages. Dependency direction: external-provider; the plugin frames Spec Chat and answers its requests; Spec Chat imports no plugin code and works unframed. Observable scope: the Proof page that opens.

The annotateanything evidence service owns which evidence is picked, text matching, the Jev judgment, and on main. Caller-facing seam: GET /criteria, as evidence-site#criteria-read defines. Dependency direction: external provider; it never calls Spec Chat. Observable scope: its JSON response.

Evidence note

Every data-acceptance-criterion on an HTTP-served spec gets an evidence note, listed first in its marker popover, once evidence loads; a criterion with no other note gets a marker for it.

An evidence note is a state label in words, a muted context line, and a small bundle link.

The criterion's marker follows its evidence: QA passed and QA passed · reworded show a small green check, since it passed and only wording changed, QA failed, QA failed · reworded, and QA stale the colored ! (Important, since it failed), and No QA yet stays the quiet grey dot. Check and ! are glyph shapes, so state never rests on color alone, and each mark meets 3:1 against the page in light and dark themes. Precedence across a marker's notes is in markers.

Every evidence label names QA, so it never reads as a Jev note in the same popover; labels stay one short line with no added box, rule, or heading.

Every label but No QA yet has context #<PR> · <age>, plus not on main when so; the label opens the bundle page at that criterion with its artifact open, through the view link /criteria returns, and bundle opens the bundle page at its top. No QA yet has neither.

Age is the capture time relative to now: minutes, hours, or days, as 5 m, 3 h, 2 d.

A picked evidence with no valid artifact still links its label; the bundle page then lands on the criterion with nothing opened.

A QA stale or reworded note adds one inline diff line: the proven text from the evidence against the criterion text as read, word by word, removed words struck through and added words underlined, so the cue survives without color. The diff wraps inside the popover and never widens the page.

Evidence notes never change a spec, the spool, a thread, or spec acceptance eligibility, and never hide or reorder content.

Ask for re-proof

Only a QA stale note gets a note button, Ask for re-proof; it opens the comment composer at the criterion and writes nothing until the reviewer sends.

Draft text, fixed: <criterion anchor> changed since its evidence (#<PR>, <capture date>): please recapture it.

A sent request is an ordinary comment: the hand-off wakes the host row's owner through host wake, and that owner runs a narrow Jev recapture of that criterion.

A spec on main, outside any lane, is registered with the operator as owner, so its request reaches the operator, who starts a small re-proof lane.

Every hosted spec has an owner: review-host register rejects a row without one. A lane spec's owner is the lane owner; a main spec's is the operator. So a request always reaches someone, and the page shows no watcher state.

Keeping the reader's place

The runtime remembers, per spec path, the nearest section anchor at the top of the viewport and the scroll offset from it, in the browser's local storage, updated as the reader scrolls and when the page hides.

On load, once the page has rendered, it scrolls back to that anchor plus the offset; an anchor in the address wins, and a missing anchor or no record leaves the page at the top.

Every storage read and write is wrapped so a sandboxed frame, a full quota, or disabled storage never breaks the page; the place is then simply not kept.

This makes Spec alone in BB keep its place across an evidence open and Back, where BB reloads the frame.

One read per page

The review server reads the evidence service's public base URL from SPEC_CHAT_EVIDENCE_URL in its environment; unset means no read and no evidence notes.

The criterion ID is branch-free, project/<project-id>::<spec path>#<anchor>, as evidence records it; the project ID is the last path part of the served root's origin URL without .git, such as spec-chat.

The viewed commit is the serving root's head, so a lane worktree and main each judge their own text.

A criterion whose served bytes differ from its bytes at head is marked uncommitted and shows QA stale, because the evidence service judges committed text only.

Each entry passes through the picked evidence's proven text and view link, which /criteria gains for this revision (annotateanything evidence-site#criteria-read); the diff compares that text with the criterion as served.

The service's relative artifact and bundle paths are joined to SPEC_CHAT_EVIDENCE_URL before they reach the browser.

A timeout, error, or non-JSON answer returns no entries; the server does not retry, and the next page load asks again.

Proof

First failing test: the review server, given a fake evidence service answering one matching pass and one material mismatch, returns QA passed and QA stale entries with absolute links.

Evidence: server and runtime tests behind a fake evidence service, and a QA bundle driven by the Jev driver on a real spec served with the real evidence service.

Non-goals

Recapturing, re-reviewing, or accepting from the page itself (Ask for re-proof only drafts a comment); evidence on stories; tracker reads; opening other links in the plugin.
