Box review service and providers

docs / specs / review-service.spec.html

Source issues: ANN-257. Boundary rule: annotateanything ADR-004, peer boundaries.

Status: under human spec review.

Spec Chat works completely alone. A box has one review service that every lane joins; the service owns its bind, port, and URL. Anything else plugs in only through the service's own state: Spec Chat publishes facts there for readers, and reads optional providers from there. Spec Chat names no reader and no provider product.

User stories

As a human reviewer, every lane on a box hands me a link on the box's one review service, so a page I can open once I can open for every lane.

As a Spec Chat user with nothing else installed, review works end to end: private by default, public when I say so once, and no capability I lack shows an error.

As another tool, I find the review service and plug an optional capability into it through its state alone, with no launch flag, environment variable, path, or port set by hand, and Spec Chat never learns my name.

Acceptance criteria

Given the box's review service running public, when a lane runs review-host register with its resources and slug and no host, port, bind, or state flag, its rows join that service and the printed URL is the service's own, the same host and port as every other lane's.

When the lane-facing register command in Spec Chat's skills and adapters is read, it is the lane command and carries no --public, --private, --proof-host, --state-dir, bind, port, or address argument; those appear only under box setup.

Given a spec path inside a worktree whose origin ends in annotateanything.git, registered as a plain path with no --base, then with --base <ref>, then in the old PROJECT_ID=ROOT:SPEC_PATH@BASE form, the first row has project annotateanything, the worktree top as root, and the merge base of HEAD with the default branch as base; the second has <ref>'s commit as base; the third registers exactly as before.

When the box's review service is dead and a lane registers, the service restarts on its recorded bind and proof host, on its recorded port while that port is free, else on another port it finds, and prints its URL; the caller passed no port.

On a box with only Spec Chat installed and no service yet, the first register starts a private loopback service and prints its ssh -L tunnel; one --public <host> makes it public and later registers join it public; with no provider files, criteria read null, Jev is off, and wake reports unavailable, with no error.

After any register starts or joins a service, registry.toml [process] holds url equal to the printed review URL, and for the box's service that file is at the stable location.

With the service running, when a provider writes providers/evidence.toml, then deletes it, the next page load reads criterion evidence from that provider's URL, then the next reads null; the server is never restarted.

When the review server's environment sets the former evidence URL or Jev key variables and no provider file exists, criteria read null and Jev is off: the environment is not read.

Given a wake provider whose check exits 0 for pane p1, and none at all, register prints wake=verified owner=p1 and a hand-off runs the provider's wake command with the owner and message; without a provider it prints wake=unavailable.

When Spec Chat's code, specs, and skills are read after the change, host wake runs only the wake provider's commands, and no pane tool is named; the host-wake states are the provider's exit codes.

On every push and pull request, CI runs the full test suite in a clean environment with no other tool of the box installed and no provider file, and it includes one contract test per provider: file present, capability appears; file absent, capability quietly absent.

Modular boundaries

The review service owns its bind, port, proof host, and URL, recorded in its own state. Caller-facing seam: review-host register, which returns the URL. Dependency direction: self-contained; no lane, skill, or brief picks a port. Observable scope: the printed URL and [process].

Readers own nothing in the service state; they read what the service publishes. Caller-facing seam: the published files and routes. Dependency direction: external-provider; readers depend on Spec Chat, never the reverse, and never write into its state. Observable scope: the published fields.

Each provider owns exactly its own file under providers/; Spec Chat owns each file's format and reads it. Caller-facing seam: the provider files. Dependency direction: external-provider; providers depend on Spec Chat's format, Spec Chat names no provider product. Observable scope: a capability on while its file is valid, off otherwise.

One service per box

The box's review service lives at Spec Chat's default service state, $XDG_STATE_HOME/spec-chat/hosting/default (~/.local/state when XDG_STATE_HOME is unset). review-host register without --state-dir joins it; if it is live, the rows are added and its URL is returned unchanged.

A new service is private on loopback. --public <host> makes it public; --private returns it to loopback. The choice, and the proof host used for a wildcard bind, are recorded, so every later register and restart keeps them. Choosing visibility is the box owner's act, not each lane's.

A dead service restarts on its recorded bind and recorded port while that port is free; otherwise it takes another free port by its own rule (an approved ingress port when public).

A lane runs only review-host register --slug <lane-key> --owner <pane> <spec path>, repeating the spec path for more specs. It names no exposure: the service already owns it, so a lane command never reads as opening ingress.

A plain spec path infers the rest from Git: root is the worktree top; project is the last path part of origin without .git, or the top directory's name without an origin; base is the merge base of HEAD with the default branch (origin/HEAD, else main), or --base <ref>. The PROJECT_ID=ROOT:SPEC_PATH@BASE form still works.

Box setup, by the box owner and outside any lane: --public <host>, --private, and --proof-host, each once.

--state-dir names a separate, isolated service for tests or deliberate isolation; lanes do not pass it.

What the service publishes

ReadHolds
registry.toml [process]pid, bind, port, host (proof host), and url, the URL the service printed.
registry.toml [[resource]]One row per registered spec: slug, project, path, root, base, accepted, owner (lane hosting).
Routes under urlSpec pages, the review index, and /api/jev/board.

Readers never write into the service state; a reader keeps its own records in its own state.

Providers

An optional capability is on while providers/<name>.toml in the service state is valid, and off otherwise, silently. A provider writes its file atomically and deletes it to unplug. The server reads the file at each use, so plugging needs no restart.

NameKeysCapability
evidenceurl: base URL answering /criteriaCriterion evidence; replaces SPEC_CHAT_EVIDENCE_URL.
jevkey: model API key; file mode 0600Jev suggestions; replaces OPENROUTER_API_KEY.
wakecheck and send: argument lists with {owner}, {artifact}, {message} placeholdersHost wake: check exit 0 means the owner resolves; send exit 0 sent, 75 deferred, other failed. Replaces the built-in pane tool calls: the host reaches owner panes only through the registered waker, and Spec Chat names no pane tool.

The server reads no provider setting from its environment.

Proof

Seam: review-host register and the review server's provider read, tested with fixture state directories and fake providers.

First failing test: a live service's registry.toml gains [process] url equal to the printed URL.
