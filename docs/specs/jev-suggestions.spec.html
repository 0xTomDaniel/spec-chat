Jev review suggestions

docs / specs / jev-suggestions.spec.html

Source issues: ANN-100.

Follows the shared Jev contract, annotateanything docs/specs/jev-seam.spec.html#contract (ANN-49): typed suggestions, show everything below threshold, never act, validated criteria, one judgment record, cache per source revision, text only, server-side key. This spec owns Spec Chat's questions, criteria, and display; no code or data is shared with annotateanything. Extends Git-derived focus and compared range.

User stories

As a reviewer in Git focus, I see which changed sections are scope or behavior changes and which are cosmetic, so I read the material ones first.

As a reviewer, an orphaned comment suggests where its passage probably moved, and nothing moves unless I click.

As a reviewer, when Jev is off, unsure, or failing, the page looks and works exactly as it does today.

As the operator, I can see for any suggestion which model, question set, and sources produced it, and with what confidence.

Where Jev runs

Only the review server calls Jev: OpenRouter model typesafe/jev-1.13 through POST /api/alpha/decisions. The browser never sees the key or the provider.

The server reads OPENROUTER_API_KEY from its environment, loaded from the box file at launch. The key never enters specs, spools, logs, judgment records, bundles, or pull requests.

With no key, the server reports Jev off and the page is exactly today's page.

The browser sends only the spec path, the compared base, and nothing else. The server builds every question from its own served file, local Git, and the spec's spool, so a public URL cannot submit arbitrary text for classification.

Change type in Git focus

Each changed root section of the current focus comparison gets one Choice question over its base text and current text: scope, behavioral, clarification, or cosmetic.

AnswerCriterionFocus treatment and badge
scope, confidentAdds, removes, or moves a capability, surface, or non-goalChanged highlight, strongest; badge Scope
behavioral, confidentAlters what the result does: a rule, interface, edge case, or criterionChanged highlight; badge Behavior
clarification, confidentSame behavior, meaning stated more preciselyChanged highlight, lighter; badge Clarification
cosmetic, confidentWording, typo, order, or style with no change in meaningDimmed, still 4.5:1 readable; badge Cosmetic
below threshold, error, timeout, oversize, or offNoneToday's changed highlight; no badge

No label hides, collapses, or reorders a section; badges carry text, never color alone.

Focus renders at once as today; labels arrive later, and a slow or missing label never blocks or shifts review controls.

When the reviewer changes the base through the range bar, the page drops all labels at once, re-diffs as today, and asks again for the new base.

Unchanged sections and pages without focus=changes are never classified.

Orphaned comment location

A thread is orphaned when its anchor no longer exists in the current spec; today it keeps its sidebar card and stored quote and shows no pin.

The server picks up to 8 current anchors whose text best matches the stored quote, then asks one Choice question over the quote and candidate texts: one candidate, or none.

A confident candidate adds Possibly moved to: <section heading> to the orphaned thread's card, with Go to, which scrolls to and outlines that section.

The suggestion never re-attaches the thread, writes a spool event, or changes status on its own.

TBD, human click: the contract allows re-anchoring by an explicit human click. Proposal: v1 ships Go to only and the agent still replies orphaned, because a Move comment here button needs a new spool event type the watcher must learn. Confirm, or ask for the button now.

None, below threshold, or unavailable shows today's card only.

Cache and judgment records

Answers are cached per source revision, section anchor, and question-set version. The revision is the compared base plus head, or the served bytes for a dirty working copy, so a new head or base classifies again and nothing else does.

A cached answer is reused without calling Jev again, so reload and repeat visits cost nothing.

Every shown or withheld answer appends one judgment record in the contract's format, #record: addresses and revision, never source text or the key.

Records are append-only JSONL in the review server's state directory on the box, outside every spool and outside Git.

Question sets and calibration

The change-type and orphan-location question sets are versioned data in this repository: instructions, the criteria above with examples, and a threshold.

Each has a small labeled set from our own history: spec commits and past atomic versus material Finish calls for change type, and ANN-30 orphaned comments, including deleted passages, for location.

A calibration command runs a set against real Jev and reports per-label precision at its threshold; below 0.9 for any label, the set stays off and its surface stays neutral.

Acceptance criteria

When a served spec change fixes a typo in one section and changes a rule in another, in Git focus with Jev on, the rule's section shows Behavior with the changed highlight and the typo's section shows Cosmetic, dimmed and still readable.

When there is no key, a label is below threshold, Jev times out or errors, or the state is oversize, that section renders exactly as Git focus does today, and review controls behave unchanged.

For any combination of labels, every changed and unchanged section stays present, in source order, and readable at 4.5:1 contrast.

When the reviewer changes the base in the range bar, old labels disappear immediately and the new base's labels replace them without a reload.

When a commented passage moves to a new section and its anchor is removed, the orphaned thread's card shows Possibly moved to: that section, and Go to scrolls to and outlines it; a deleted passage shows today's card only.

Across a review session with Jev on and no human click, the spool, thread statuses, Finish eligibility, and spec bytes match a session with Jev off.

When the same page, base, and head load a second time, no new Jev call is made and the same labels show.

For every shown or withheld answer, one judgment record carries every contract field, with no source text, and no page, record, log, or response contains the key.

When a client sends section text or any parameter beyond path and base, the server ignores it and classifies only its own served file, Git, and spool.

When calibration scores a set below 0.9 precision for any label, that set reports off and its surface stays neutral.

Modular boundaries

The review server's Jev seam owns questions, provider calls, thresholds, cache, and judgment records. Caller-facing seam: GET /api/jev?path=<spec>&base=<id> returns on or off, a label or none per changed root anchor, and a candidate anchor or none per orphaned thread id. Dependency direction: calls Jev on OpenRouter as an external provider and reads local Git and the spool; nothing calls back into the runtime. Observable scope: the JSON response and judgment records, in single-root and registry modes.

The browser runtime owns badges, focus treatments, and orphan hints. Caller-facing seam: the rendered Git focus and orphaned thread cards. Dependency direction: self-contained within Spec Chat; consumes the seam route and holds no model, threshold, or key logic. Observable scope: what the reviewer sees in focus and on orphaned cards.

Question sets own criteria, examples, thresholds, labeled sets, and calibration results. Caller-facing seam: a question-set id and version, and the calibration command. Dependency direction: self-contained data read by the seam. Observable scope: which sets are on and their measured precision.

Proof

Smallest first failing test: a fake provider answer below threshold returns no label and appends a withheld record.

Evidence: server tests behind a fake provider, runtime tests behind a fake route, a calibration report per set against real Jev, and a QA bundle of Git focus and an orphaned card on a real spec change.

Non-goals

Generated text of any kind (ANN-96), other providers, or budget rules.

The contract's later slices: comment intent, proof coverage, staleness, traceability, and board urgency.
